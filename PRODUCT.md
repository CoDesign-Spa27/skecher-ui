# Product

## Register

product

## Users

Frontend engineers and product designers use Skecher UI while evaluating motion-heavy React components for their own interfaces. They are usually in implementation mode: checking the behavior, copying install commands, and adapting source files into an existing design system.

## Product Purpose

Skecher UI is a component registry and documentation site for polished React UI primitives. It should help users preview components quickly, understand the dependencies and source shape, and move from demo to production without losing ownership of the final code.

## Brand Personality

Precise, expressive, and craft-led. The interface should feel focused enough for documentation work while still carrying the motion polish that the components themselves promise.

## Anti-references

Avoid generic SaaS landing-page scaffolding, oversized marketing sections, decorative card grids with no workflow value, heavy glass effects, and motion that distracts from component evaluation.

## Design Principles

- Let the component behavior lead the page.
- Keep docs navigation obvious and task-oriented.
- Use motion only for feedback, state, and gentle orientation.
- Favor readable, restrained product UI over decorative spectacle.
- Make installation and evaluation feel close to the source code.

## Accessibility & Inclusion

Aim for WCAG AA contrast, keyboard-accessible navigation, visible focus states, reduced-motion-safe transitions, and media controls that remain available to users who need captions, pausing, or manual playback.
